# Content blocks

Blocks that are more than markdown are written as marker lines, HTML comments other markdown apps don't show. Built: the syntax, blocks Blank can't show, the table of contents, forms (flow, grids and positioned frames), diagrams (source blocks, below), and embeds, whose plugins are to come. The user finds them in the blocks pane and works with them through the block toolbar; neither says how a format stores them (the docs explain that in one closing section, `docs/guide/blocks.md#storage`). The OpenDocument export doesn't keep blocks yet.

## Naming

- In the UI and the docs: "blocks", "Table of contents" (sentence case), "forms", "form definition" (what a YAML file says), "Your own forms", "drawings" (embeds), "Diagram", and a block's "Description" (its alt text). Never "template": the folder is `<app config>/forms`, the module `src/forms/library.ts` (`loadForms`, `formsDir`). Word's gallery value `Table of Contents` stays as Word writes it.
- What stays as it was, since files hold it: the ids `blank/<name>` and `user/<file name>`, the marker key `def=`, and the Custom XML namespaces.

## The blocks pane (`src/ui/BlocksPane.vue`)

- `insert.block` (`Mod-Alt-b`) runs `toggleBlocksPane`: it opens the pane (`blocksPaneOpen`, persisted under `blocksPane` in `src/storage.ts`) and asks for the focus in its search (`focusBlocksSearch`), or closes it while it has the focus (`blocksPaneFocused`, part of `uiTakesFocus`). The pane handles the same key itself, since the editor doesn't see keys while the pane has the focus.
- `readBlocks` (`src/editor/commands/contentBlocks.ts`) reads the choices whenever the pane opens: the table of contents (group `contents`), Blank's and the user's forms (`forms`, an unreadable one disabled with the reason as its description; a second file of one id is offered as `user/<name>~2`, disabled, so ids stay unique), and the registered embed types (`drawings`). It publishes them in `blockChoices` without their insert functions, which it keeps by id; the pane runs `insertBlock(id, at?)`.
- `blocksPaneModel.ts`: `groupsOf` (the groups in that order, search over name and description, empty groups left out), `tileStep` (arrow keys in rows of two, ↑ from the first row back to the search), `formWireframe` (a form's tile drawn from its layout: stacked fields, a grid's cells side by side, frames at their place on an A4 sheet), `blocksDock` (the room it takes: 248 px from `OUTLINE_BREAKPOINT` on, where `body.blocks-docked` moves `#page-view`'s left edge; it floats below). The outline's placement subtracts that room (`layoutWidth` in `outlineModel.ts`).
- Its surface is the `side-pane` mixin (`src/scss/_controls.scss`) with `SidePaneHead.vue`, made to be shared with the outline's open list.
- `insertTopBlock` puts a block in place of the empty paragraph the cursor is in, after the block the cursor is in, or at a place between two top-level blocks it is given (a drop), selects it (a `NodeSelection`) and announces "‹Name› inserted". Enter or typing on a selected form goes into its first field (`enterForm` in `blockTools.ts`, through the forms plugin's `fieldEntry`, which enters a table field under its header row), so typing never replaces a form just inserted.

## Dragging blocks

- A tile dragged onto the pages (`src/ui/tileDrag.ts`) and a selected top-level block dragged on the pages (`movesBlock`/`moveCandidate` in `src/editor/pagePointer.ts`, through `pageMove.ts`) drop between two blocks at the top of the document: `gapAt` (`src/engine/geometry.ts`) takes the block under the point and its upper or lower half, `pageDropGap` holds the place, and `BlockMarks.vue` shows `gapLine` as `.block-drop-line` (the accent, a dot at its start). A move drops through `pageDrop`, which re-selects the node; Ctrl (Alt on macOS) copies.
- Both follow pointer events (4 px to start, pointer capture, Esc or letting go off the pages cancels), never HTML5 drag and drop: WebKitGTK and Tauri's own handling of file drops (`dragDropEnabled`) make HTML5 drops unreliable in the webview, and WebDriver can't drive them, so E2E couldn't test it.
- `BlockMarks.vue` also outlines the content block under the pointer (`pageHoverBlock`, set by `PageView.vue`'s hover through `contentBlockAt`) with a hairline, except the selected one, whose ring is `.page-node-selection` (2 px in the accent, as for every selected node).

## Copying and removing

- The plain text of a copy that holds a whole top-level content block is its markdown (`blocksMarkdown` in `src/editor/plugins/blockClipboard.ts`, through the `clipboardTextSerializer` of `tableClipboard`, after `tsvOf`), with the definitions of its forms. Text, text in a form's field and cells copy as before.
- `blockRemovals` (`src/editor/plugins/blockRemovals.ts`) announces "‹Name› removed" (or "N blocks removed") for every user change that deletes a top-level content block: Delete, Backspace, cut, the context menu, the toolbar. It says nothing for a move (`uiEvent: "drop"`), undo and redo, repairs (`addToHistory: false`) and a block replaced by one of its kind (a table of contents' settings). Names come from `blockName` (`src/markdown/blocks/names.ts`).

## Markers (`src/markdown/blocks/args.ts`)

- `<!-- blank:NAME@FORMAT key="value" … -->` opens a block or is one; `<!-- /blank:NAME -->` closes it. `FORMAT` versions the block's own syntax, apart from any form definition or payload version in its arguments.
- Values are always double-quoted, with `& " < > -` and line breaks as character references, so `--` never appears in a comment and a marker stays on its line. Known keys are written in the type's order, unknown ones after them and kept.
- A comment is a marker only with a name right after `blank:` (`looksLikeMarker`), so a note like `<!-- blank: fill in later -->` stays text.
- A marker stands alone on a line, at column 0 of the document's top level: never in a quote, a list, a cell or indented. `<!--` typed as text is written `\<!--` (`serializer.ts`), so typed text never becomes a marker.

## Reading (`src/markdown/blocks/rules.ts`)

- `blankMarker`, a block rule before `table`, reads a marker line as a flat `blank_marker` token. It decides by the raw line (column 0 of the source, `tShift` 0), not by `state.parentType`, which markdown-it sets to `paragraph` or `table` while those look for their end. In silent mode it says that any such line ends the block before it, so a marker right after a paragraph, a list, a quote or a table row is never swallowed as text.
- `blankBlocks`, a core rule right after `block`, pairs the markers (by name, nesting counted) and turns them into blocks. It never searches for a closing line in the source, so a marker inside a fenced code block can't close a block.
  - A block of one line whose name and format `src/markdown/blocks/atoms.ts` knows (`toc@1`) becomes its node, with its arguments read into the node's attributes (`read`) and written back (`write`, through `formatAtom`), unknown ones kept in `extra`. It never pairs with a closing marker, so a stray `<!-- /blank:toc -->` can't swallow the text after it. With arguments it can't use it is an unknown block of that one line.
  - The definitions sections (`definitions@1`, only YAML code blocks inside) are read first, as they stand at the end: each code block Blank can read (`readDefinition`, checked by `checkDefinition`) goes into the doc attribute `definitions` by its key, `<id>@<version>#<hash8>` (`definitionKey`, a hash of what it says, computed, never stored); the others, as written, into `rawDefinitions`.
  - A form (`form@1 def="<key>"` … `field name="…"` … `/form`) whose definition is there becomes a `form_block` of `form_field`s. A form without its definition, with a field its definition hasn't, other markers in it, or blocks a field can't hold (a page break) stays an unknown block.
  - Every block Blank doesn't know, and every marker that doesn't pair up, becomes one `unknown_block` holding its source lines, exactly as written (after markdown-it's line-ending normalization). It is written back unchanged.

## Unknown blocks

- `unknown_block` is in the `top_block` group: the doc holds `(block | top_block)+`, quotes and lists only `block+`, so content blocks can't end up where the markdown can't hold them.
- The pages and the PDF show it as a `boxed` engine item with `unknownLabel`; the Word export leaves it out with a warning, the PDF export warns that it is a box; without the engine it is a `pre.unknown-block`.
- The table guard keeps a paragraph before, after and between content blocks, as around tables (`standsApart` in `src/editor/plugins/tables/util.ts`), since the cursor can only select them.
- A stored document (localforage JSON) with a top-level node type this Blank doesn't know is restored with that node as an `unknown_block` (`restorable` in `src/storage.ts`), its JSON kept in a `blank:stored@1` block.

## Table of contents

- The node `toc` (`depth`, `title`, `extra`), written `<!-- blank:toc@1 depth="3" title="Contents" -->`. It lists `listedHeadings(doc, depth)` (`src/markdown/headings.ts`): the headings `isListed` says are the document's, the same ones the outline shows and the PDF bookmarks. Everything that counts entries uses it: `flatten.ts` (`tocEntries`), the editor's view and `followEntry`, the Word export; and the engine counts the same headings by their `listed` flag.
- Inserting: from the blocks pane, and `[toc]` (or `[TOC]`, `[[_TOC_]]`) + Enter on an empty top-level line (`autocomplete/transformers/toc.ts`).
- Editing: Enter on a selected one, or the toolbar's pencil, opens its settings below the pencil (`editToc` → the request `tocPopover`, `TocPopover.vue`, `tocPopoverModel.ts`): "Headings it lists" ("Heading 1", "1 – 2" … "1 – 6") and "Title". Each change applies at once as one undo step (`apply`, `setNodeMarkup`, the title's typing grouped by the history's delay); Esc, Enter in the title or a press elsewhere closes it and gives the focus back with the table of contents selected. Ctrl+Click on an entry scrolls to its heading at the reading line (`followEntry` in `src/editor/plugins/toc.ts`). Its node view lists the headings in the hidden editor, for screen readers and for the view without the engine; it follows the `headings` store.
- Pages and PDF: see `layout-engine.md` (the `toc` item).
- Word export: docx's `TableOfContents`, subclassed for the page numbers' tab stop at the text width (`tocClass`), its title a `TOCHeading` paragraph before it, and marked from Word's gallery of tables of contents (`TOC_NAME`, `markTocs` in `fixups.ts`). Its cached entries are the listed headings with Blank's page numbers (`tocContext`, from the page engine's `tocNumbers`, after it laid out the rest of a long document), linked to `_BlankToc<n>` bookmarks on the n-th listed heading; both go by the headings' order in the document, never by node, since ProseMirror may share one node between two places.
- Word import (`src/importers/docx/toc.ts`, before mammoth): a content control from that gallery, or a bare `TOC` field whose paragraphs hold nothing else (not a table of figures, `\c`), becomes a `BlankToc` marker paragraph holding the marker line, which `cleanup.ts` reads with `readAtom` and writes as the schema's `toDOM` does. LibreOffice writes `\f` in its tables of contents of headings too. `scripts/build-docx-fixtures.sh` builds pandoc's and LibreOffice's from `toc.md`.
- Pasting: content blocks pasted into a table, list or quote go after it, at the top of the document (`pasteTopBlocks`), instead of splitting it. Pasted or Ctrl-dragged embeds whose id the document has get new ones (`apartFrom` in `src/editor/plugins/embeds.ts`, for paste and `dropMoved`).

## Forms

- A form definition says what a form holds (`src/markdown/blocks/definitions.ts`): `version`, `name`, `description`, `newPage`, its `fields`, each a `name`, `label`, `kind` (`text` with a `style` p or h1–h6, `image`, `table` with `columns`, `rich`) and `placeholder`, and its `layout` (`src/markdown/blocks/layout.ts`: `{ field }`s and `{ grid: { columns, gap }, cells }`, whose cells are columns of fields; `checkLayout` wants every field once, in the order of `fields`, no grid in a grid, up to 4 columns of lengths or `fr` shares; `placesOf` gives each field in a grid its band, the row of the grid, its column and the tracks). Unknown keys make it unreadable, so a newer Blank's definition is kept as written. Forms are Blank's own (`src/forms/*.yaml`, `blank/<name>`) and the user's YAML files in `<app config>/forms` (`user/<file name>`), read by `loadForms` (`src/forms/library.ts`) whenever the blocks pane opens; a file with a mistake shows in the pane, disabled, with what's wrong in its tooltip.
- A placed form keeps a copy of its definition in the doc attribute `definitions`, by its key (read it with `docDefinitions`/`definitionOf`/`formDefinition`, which never take a key from the object's prototype); `serializeMarkdown` writes the ones forms use (and blocks Blank can't show name, scanning their `def=`) at the end of the file, with `rawDefinitions` as they were. So a form stays as it was placed whatever becomes of its form definition.
- `form_block` (`def`, `extra`) holds `form_field`s (`name`), which hold `field_content`: the blocks of the document but page breaks and content blocks. `src/markdown/blocks/forms.ts` is the model: `createForm`, `fitField`/`fitForm` (a text field one textblock in its style, an image field one paragraph, a table field a table, the fields in the definition's order, no page breaks), `settleForms` (what `parseMarkdown` and the Word import give: forms as their definitions say, and those without one as the blocks they held), `fieldAt`, `fieldSpec`, `formBlocks`, and `isEmptyField` (the one empty textblock of its kind: written as nothing in the file, and what shows the placeholder on the pages and in Word).
- The editor (`src/editor/plugins/forms/index.ts`, before autocorrect and the table keys): the guard repairs the forms a transaction changed with `fitForm`, keeping the cursor in its field at the same text offset; gives a form pasted from another document its definition, which `transformCopied` recorded from the document it was copied from; and unwraps a form whose definition is nowhere; Tab and Shift-Tab go from field to field (a table takes them up to its last cell, a list or code where they can; a table field is entered under its header row), Enter goes on from a text or image field, Escape selects the form; a pasted slice that starts or ends in a form is that form's blocks there (`unwrapForms`), a whole form stays one; the field view names a field by its label (`aria-label`). Page breaks can't be put into a form (`outsideForms`).
- Pages and PDF: `flatten.ts` lays out the fields' blocks with the document's spacing, in the context of the top level, so headings in them are listed, chapters and start new pages as `new-page-before` says, as Word's heading styles do; an empty field's textblock gets its placeholder as `hint`, which the engine draws as `Part::Hint`, on the screen only; the first item of a form whose definition says `newPage` gets `pageStart`, which opens a page as a page break does. The items of the fields in a grid get a `column` (index, tracks, gap, and `start` on the first item of each band, patched on its record like `pageStart`), and their headings aren't `top`: no page starts or chapters in a column. Each column starts after the block before the band.
- Word: a band of a grid is a table of one row without lines (`grid` in `src/exporters/docx/index.ts`), its cells as wide as `trackWidths` says, with the room between columns as cell margins, each holding its fields' content controls and ending with an empty paragraph, as Word wants; a field in a column is written at the column's width (`contentWidth` and `maxImageWidth` while it is written). The table stands in a content control tagged `blank:grid` (`GRID_TAG`); `contentControls` turns the markers in table cells into controls too. The import (`markForms`) reads such a table's cells one column after the other and leaves out their empty paragraphs.
- The block toolbar (`src/editor/plugins/blockTools.ts`, `src/ui/BlockToolbar.vue`, state `blockToolbar`) sits above a form while the cursor is in one (not in a table there, whose toolbar goes first), above an open source block, and above any selected content block, unknown ones included ("Block Blank can't show"): the block's icon and name, Settings (the pencil, its key `block.settings`, only where `editBlock` applies) and Remove (the bin, "Remove block", whose tooltip shows Backspace while the block is selected), drawn by `ToolbarButton` as the table toolbar's are. It also handles the paste of content blocks (`pasteTopBlocks`). It shares `placeToolbar`, the `.toolbar` styles and `followLayout`/`boxOnCaretPage` (`src/editor/plugins/followLayout.ts`) with the table toolbar.
- An empty image field's textblock is sent with `picture: true`: the engine draws its hint in the middle of a box of a picture's size (`Role::Placeholder`, `Part::Hint`, so on the screen only; the PDF keeps the room), and a press on it opens the image dialog (`choosePicture` in the forms plugin, on `PAGE_PRESS`). `pictureBoxAt` tells whether a point is on that box, for the press and for the page view, whose `on-picture` class shows the pointer as a hand there.
- Frames (`{ frame: { x, y, width, height }, field }`, one field each, no table): they come first in the layout, the definition must say `newPage`, and `flowTop` (also only with `newPage`) says where the other fields start on the first page, from its top edge. `flatten.ts` gives a frame's items `frame` (x, y, width in points; `start` on the first, patched like the band starts), headings in frames aren't `top`, and the first item in the flow gets `flowTop`. Word: the field's paragraphs get a page-anchored paragraph frame (`frameOf`, height as at least), and the first flow paragraph space above it that starts it at `flowTop` (`startAt`), which `spaceTopLevel` keeps; paragraphs in frames aren't the previous block there.
- Without the engine, the fields of a grid or a frame stand one below the other: ProseMirror's DOM has no element for a column.
- Headings in forms are the document's: `forEachHeading` (`src/markdown/headings.ts`) walks the top and the forms' fields, for the outline, `listedHeadings` and so tables of contents.
- Word (`src/exporters/docx/forms.ts`): a form is a locked group content control (`blank:form@1:<key>`, named after its form definition) holding a locked content control per field (`blank:field:<name>`, named by its label); an empty field shows its placeholder (`showingPlcHdr`, the style Placeholder Text). docx can't write content controls, so the export writes marker paragraphs (`BlankControlOpen`, `BlankControlClose`) that `contentControls` in `fixPackage` turns into them, moving "page break before" onto the form's first paragraph (onto an empty paragraph before a table, which can't have it). `spaceTopLevel` passes over the markers. The definitions the forms use go in a Custom XML part (`customXml/item1.xml`, namespace `DEFINITIONS_NAMESPACE`), as a YAML list (`writeDefinitionList`, read back by `readDefinitionList`).
- Word import (`src/importers/docx/forms.ts`, before mammoth): `readDefinitions` reads that part; `markForms` turns Blank's group content controls into marker paragraphs (`BlankFormMarker`, made by `markerParagraph` in `xml.ts` like the page break and TOC markers) holding the marker lines around the fields' content (none for a field showing its placeholder; what isn't in a field of Blank's goes into the field before). It runs before `markPageBreaks` and takes the form's "page break before" off its first paragraph, putting a page break marker before the form when its definition doesn't say `newPage`. `cleanup.ts` (`forms`) turns the markers into `section[data-blank-form]` and `div[data-blank-field]` for the schema, and `settleForms` then fits them.
- Not yet: static content (a letterhead's logo), per-field records in `flattenBlocks` (a long field lays out its whole form again on each key), and updating forms already placed to a newer form definition.

## Embeds

- `<!-- blank:embed@1 type="ns/name@1" id="…" width="…" alt="…" -->`, an optional data fence (`json` or `xml`), an `svg` fence, `<!-- /blank:embed -->` (`src/markdown/blocks/embeds.ts`: `checkEmbed`, `writeEmbed`, `embedSrc`, `embedLabel`). Anything else between the markers, no drawing, a type that isn't namespaced or a width that isn't a length makes it an `unknown_block`. The drawing is cleaned by `sanitizeSvg` (`src/markdown/blocks/svg.ts`: an allow-list of elements; no scripts, foreignObject, event attributes, links but `#…` and embedded pictures, imports or outside `url()`), on reading, on pasting (the `figure[data-blank-embed]` holds all attributes as JSON) and on editing.
- `embed` is an atom of `top_block` with all of it as attributes. It flattens to an `image` item of `embedSrc` (a `data:image/svg+xml` URL), at `width` if it says one, so the page view, the PDF (`prepareImages` collects embeds too and rasterizes them) and Word show it as they show images.
- Word: a picture in a content control `blank:embed@1:<id>`, the embeds' attributes by id as JSON in a second Custom XML part (`addEmbeds`, `EMBEDS_NAMESPACE`; both parts written by `addCustomPart`). The import (`src/importers/docx/embeds.ts`) turns such a control into a marker paragraph of that JSON, which `cleanup.ts` (`embeds`) makes the figure the schema checks; without the part, it stays a picture.
- Types: plugins (later) register an `EmbedType` (`src/embeds/registry.ts`: `type`, `name`, `edit(data)` → data, svg, width, alt). The blocks pane offers the registered ones under Drawings (`makeEmbed`), and `editBlock` (in `contentBlocks.ts`: `editToc`, else `editEmbed`, which keeps the embed's id) edits a selected table of contents or embed of a registered type, on Enter and from the block toolbar's pencil (`blockTools.ts`), which shows only when it applies. A pasted embed whose id the document has gets a new one (the `embeds` plugin). Only the tests register a type (`src/test/embeds.ts`). The plan's `png2x` from the plugin isn't there: Blank rasterizes the SVG itself, which is enough as long as drawings don't need fonts the webview lacks.

## Block settings and capabilities

- `block.settings` (Shift+Enter, bindable; `blockSettings` in `contentBlocks.ts`) runs `editBlock` (`editToc`, `editDiagram`, `editEmbed`): the settings of the selected block, or of the open source block. On a selected content block without settings it returns true and does nothing, so the hard break never replaces a block. `keymap.ts` chains the configured Shift-Enter before its own hard break, which would otherwise overwrite it. Enter on a selected table of contents still opens its settings; on a source block it opens the source.
- `editBlockSettings` (`src/editor/commands/blockSettings.ts`) is what every block's settings share: the toggle (the key or the pencil again closes them), the anchor (`boxOnCaretPage`), and `apply`, which re-reads the node at its position, skips what changes nothing, and re-selects it. The request is a `BlockSettingsRequest<T>` (`src/state/dialogs.ts`: `anchor`, `values`, `apply(values)`, `close`); `tocPopover` and `diagramPopover` are two. Their components sit on `components/BlockPopover.vue` (placement under `SETTINGS_BUTTON`, `useDismiss`, Enter in a text field closes, the `block-popover` styles).
- What a block can do is in its node spec, `blockCaps` (`src/markdown/blocks/caps.ts`): `align` (the toolbar's align buttons, through `alignedBlocks` in `align.ts`; written as the `<div align>` around it; no justify for blocks without text) and `width` (`WIDTHS`: Fit, 50 %, 75 %, 100 %; `parseWidth` also reads pixels and lengths another file wrote, which `widthChoice` shows as none chosen and `widthWritten` keeps). Diagrams have both, images `width` (written `<img width>`, see `alignment.md`).
- Errors: what is drawn on the page is ink (a source block's error is a `boxed` engine item); a UI surface shows errors in `--spelling-color`.

## Source blocks and diagrams

- A source block holds its source and shows what it makes (`src/sources/registry.ts`). `sourceBlockSpecs(name, { attrs, caps, group, check })` (`src/markdown/blocks/sourceBlock.ts`) makes its two nodes: the wrapper (`spec.sourceBlock`, isolating, selectable, `group` top_block by default, its attributes as JSON on a `figure`, checked by `check` on paste and Word import) and `<name>_source` (`text*`, `code: true`: no spell check, autocorrect or marks; Tab indents as in code; tabs are written as they are). The wrapper isn't a textblock, so Backspace after it selects it.
- A kind of source (`registerSource`): `node`, `lang`, `label(source)` (the description where none is given, e.g. "Flowchart"), `render(source)` → `Rendered` (`{ok: true, data}`, `{ok: false, error, line}` or `{ok: "unavailable", reason}`), and optionally `debounce`, `inline`, `item` (its own engine item in every state) and `preview` (its own engineless preview). Display maths is the next kind.
- `src/sources/store.ts` renders and keeps: by `keyOf(kind, source)` (`blank-vector:<kind>:<fnv1a>-<length>`, also the drawing's image `src`); synchronous results at once, slow ones one after the other; while typed, after `debounce` (250 ms); an LRU of 200; `renderStates` bumps on each result; `renderAll(doc)` before an export; `sourceWarning` for what couldn't be drawn.
- A rendered drawing goes into `src/engine/vectors.ts`: its SVG with `ink(<strength>)` for its colours, which `inked(svg, color)` turns into a colour (`inMarkup`: tags and styles only, never the text of labels). The diagram module (`diagramModule.ts`, see `layout-engine.md`, Modules) draws it from the SVG inked in `rgb(1,2,3)` (`DRAWING_INK`, `INK` in the module), a colour no author writes, which it takes as the ink at a strength, so an author's own black stays black (`drawVector`, `drawAll`, `drawingOf`; `drawnVectors` in `src/state/drawings.ts`); `pageView.ts` gives each engine the drawings its document shows (`addDrawings`, through `createDrawingSync` in `src/engine/drawings.ts`, which a kind of drawing shares) and lays the blocks out again when one is drawn (the picture's record key says `drawn`). Until then, and if the module can't load, the screen shows the SVG as a picture (`vectorPicture`, per ink, with Blank's Plex as `@font-face` data, since an SVG picture can't use the webview's fonts), and the PDF a PNG of it. Word gets the SVG with a PNG fallback either way. `imageSizes` and the painter know vector `src`s; `vectorPictures` and `drawnVectors` (`src/state/drawings.ts`) repaint and re-sync.
- The editor (`src/editor/plugins/sourceBlocks.ts`): a source block is open while the selection is in its source (`openSourceAt`, plugin state `{open, preview}`, `preview` the last drawing that worked). Enter or typing on a selected one opens it (`enterSource`, through `enterBlock` in `blockTools.ts`), and so does a click on a closed one (its `PAGE_PRESS` handler, without modifiers; the arrow keys still select it first); Esc closes it to the block selection (`leaveSource`). Enter opens a block's settings only while it's selected (a `NodeSelection`): in an open source it's a new line, and Shift+Enter opens the settings there. The plugin view requests renders, and says an error once it stays a second. Its node view shows the source, what's wrong (`.source-error`) and, without the engine, what it makes (`.source-preview`; the source hides while closed, through the `open` decoration).
- Pages (`sourceBlock` in `flatten.ts`, through `SourceView` in `SyncOptions`): closed, a picture item (`picture`, shared with images and embeds) of its key, with `share`, `caption` and `align`; open, or failed, its source as a code item at `pos + 1`, then the preview picture and a `boxed` error at the block's end, so positions stay in order. `pageView.ts` re-flattens the blocks whose open state or preview changed, and the source blocks when a render lands; a hit on a preview selects the block, and a closed source block is a leaf for ↑/↓. Exports flatten with `export: true`: closed, and a failed one as its code only.
- Diagrams (`src/diagrams/`): Mermaid 12, loaded on the first render (`mermaid.ts`, with `polyfills.ts`; layout dagre, look classic, `htmlLabels: false`, strict, Plex, a grey palette). `render.ts` sanitizes, sizes it from its viewBox and recolours it (`recolor.ts`: every colour becomes ink at its darkness, `style`/`classDef`/`linkStyle`/`%%{init}%%` colours stay).
