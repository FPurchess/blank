# Signing

Blank signs what the user writes by exporting a signed PDF; a markdown file never holds a signature. It also fills in and signs the PDFs the user received, in PDF tabs, checks the signatures of the PDFs it opens, and keeps the certificates the user trusts (`trust.rs`, see `pdf.md`). The plan is the e-signing plan; this is what is built.

## The user's signature and initials

- Made in `SignatureDialog.vue` (request `signatureDialog`, opened by `openSignatureDialog` in `src/editor/commands/signing.ts`): Draw (`SignaturePad.vue`, strokes in the pad's own units, `src/signing/pad.ts`), Type (one of `SIGNATURE_FONTS`) or Image (`chooseImageFile`, then `removeBackground`).
- Every kind becomes the same thing: a transparent PNG of the ink, trimmed (`renderMark`, `src/signing/render.ts`; the pixels through `src/images/codec.ts`, the only decoder, and the pure `src/signing/ink.ts`). The pages, the PDF and Word show it as any image, so the layout engine needs no signature fonts.
- Kept as one JSON file each, `signing/signature.json` and `signing/initials.json` in the app config dir (`src/signing/profile.ts`): how it was made, so the dialog opens it as it was, and the PNG as a data URL. Read once, when first needed (`loadMarks`, `src/signing/marks.ts`, again after a failure; `saveMark` and `forgetMark` wait for it, so a late read never overwrites them), published in `savedMarks`. Saving the saved picture on Image unchanged only closes the dialog: cleaning the cleaned PNG again would wear it down. Where the user signed last is `signingPlace`, persisted in localforage like the theme, and remembered once a signed PDF is written.
- The focus: every dialog here gives it back to where it was opened from, on cancel and on success (`cancel` and `done` in the requests): the editor's `view.focus()` from a command, or `focusBack(opener)` (`src/dom.ts`, after the next render, else what took the opener's place, else the first control of the dialog it was in) from Settings or the Sign dialog, which stay open below.
- The fonts are the upstream TTFs in `fonts/`, as they are. Only the webview loads them (`src/signing/fonts.ts`, `FontFace` from the TTF's URL), when the dialog opens: no woff2 copies, so nothing is converted. Dancing Script has a Reserved Font Name, so its file must never change, like Plex; Pinyon Script, Ms Madi and Caveat have none.

## Signature blocks

- `ATOMS.signature` (`src/markdown/blocks/atoms.ts`): `<!-- blank:signature@1 role="…" name="…" place="…" date="signing|none|YYYY-MM-DD" width="NN%" -->`, defaults left out. One signer per block; a contract for two has two blocks. Its words (the lines under the line, its label) come from `src/markdown/blocks/signature.ts` for the pages, the editor's DOM and Word alike.
- The engine item `signature` (`items/signature.rs`): `SIGNATURE_ROOM` above a line `share` of the text's width (0 sends none, for the engine's `SIGNATURE_SHARE`), the image standing on it once signed, else the hint on the screen only (`Part::Hint`), then the lines as extras. Word mirrors `SIGNATURE_ROOM` and `SIGNATURE_SHARE` in `signature.ts`, which `signature.parity.test.ts` compares with the Rust source.
- The lines (`signatureLines`): dates are written as Settings ▸ Signing ▸ Date says in the document's language (`signingDates`, `src/state/signing.ts`), fixed ones too, on the pages (`SyncOptions.dates`, part of what makes the page view flatten again), in the PDF and in Word; the editor's DOM writes ISO dates, having no settings. `date="none"` always leaves a line to write the date by hand. A fixed date must be a day of the calendar (`calendarDate`).
- A signed export fills one block: `ExportContext.signed` (`SignedBlock`: pos, the PNG, who/where/when) goes to `flatten`/`flattenBlocks` (`FlattenOptions`) through the export's own engine (`PageEngine.sync`'s `signed`, part of its sameness key, so no sync keeps a block an earlier one filled in) and the PDF worker's job; the PNG goes into the export's images under `SIGNATURE_IMAGE`. A picture that can't be read fails the export.
- Settings: `SignaturePopover.vue` (request `signaturePopover`) on `components/BlockPopover.vue`, like the table of contents', opened by `editSignature` in `editBlock`'s chain. Width: 50% (the default, written as nothing), 75%, 100%. To move onto `blockCaps.width` once it lands.
- Word: a content control tagged `SIGNATURE_TAG` holding the marker line as hidden text; the import (`signatures.ts`) turns it, and Word's own signature lines (`o:signatureline`), into marker paragraphs of `ATOM_STYLE`, which `cleanup.ts` reads with `readAtom` like a table of contents.

## Certificates and digital signatures (native, `src-tauri/src/signing/`)

- Ported from the spike (`spike/signer` on `spike/signing`, with its SPIKE.md): `keys` (a P-256 key and a self-signed certificate made with rcgen, for document signing, in a PKCS#12 file of 600,000 PBKDF2 rounds, returned with its identity so it isn't read back; any .p12 read, NSS's BER ones through a shim that lets p12-keystore check the MAC on the original bytes and then reads the DER copy without one; `OpenError` says why one doesn't open: `WrongPassphrase`, `Unsupported`, `Malformed`), `cms` (CAdES-BES SignedData over the byte ranges, ESS signing-certificate-v2, no signing-time; a timestamp token as an unsigned attribute), `tsa` (RFC 3161 over reqwest, only the signature value's SHA-256 sent), `pdf` (lopdf's incremental update with our guards: the old trailer cleaned, reconstructed xrefs, encrypted files and DocMDP P=1 refused; a /Sig field and widget with an empty appearance, since the block is in the page content and Blank draws no frame), `verify` (every signature, against USF and wrapping attacks; `valid()` doesn't cover later bytes, `covers_the_whole_file()` does), `certificate` (`CertificateInfo`, the one summary of a certificate, and `common_name` from the name's parts), `commands` (what the webview asks for). HTTP clients come from `src-tauri/src/http.rs`, which installs rustls' provider.
- The key and certificate are `key.p12` and `certificate.cer` in the app config's `signing` folder. The key never goes to the webview: the passphrase comes once per signing (`signing_check_passphrase` before anything is exported, then `signing_sign_pdf`, see below), and a signed PDF is checked with `verify` before it's returned (`check_signed`: valid and covering the whole file, and with a timestamp server a timestamp that holds, else `TimestampUnusable`). `key.p12` is written 0600 on unix, both files through temp files, under one lock (`FILES`) with removing and exporting them; a key there is replaced only when the call says `replace` (else `keyExists`, which the webview turns into `ConfirmDialog`'s "Replace your key?"), and if the certificate can't be put in place the old key comes back (`keep_files`). An email that isn't ASCII is refused with a sentence (rcgen can't hold it), in `certificateDialogModel.ts` and natively. The signature names the certificate's holder (its common name) as /Name, never the block's name.
- Errors are typed, never matched by their text: `keys::OpenError` and `signing::Refusal` (`Restricted`, `Certified`, `NoTimestamp`, `TimestampRefused`, `TimestampUnusable`, whose text is the user's sentence). They're logged by context and kind only (`forTheLog`), never their text, which crypto crates may fill with what they got; the user gets fixed sentences (`SigningError`: `wrongPassphrase`, `noCertificate`, `keyExists`, `failed`). Passphrases are `Zeroizing<String>`.
- The crypto crates are optimized in debug builds (the dev profile in `Cargo.toml`), or opening a key takes minutes; the tests make keys with few rounds (`create_certificate_with`).
- Webview: `src/signing/ipc.ts` (every call; `signingMessage(error, fallback)` with a fallback per action, `signingKind` for the log), `src/signing/certificate.ts` (`signingCertificate`, read once; made, imported, exported, removed after `confirmRemoval`'s question in `ConfirmDialog.vue`, which offers Back up key… first; failures through `reportSigningFailure`), `CertificateDialog.vue` (request `certificateDialog`), `CertificateRows.vue` in Settings ▸ Signing, and the Sign dialog's Sign as with the passphrase.
- Making a key or checking a passphrase takes seconds: the Certificate dialog says so ("Creating…", a note in a live region) and the Sign dialog ("Checking…"), and neither can be cancelled meanwhile (Cancel and Esc wait), since the certificate or the PDF would still come. Removing the signature or initials asks nothing: they're made again in a moment.

## Export signed PDF

`exportSigned` (`export.signed_pdf`, `Mod-Alt-Shift-p`): no block, a notification; no signature yet, the signature dialog first; then `SignDialog.vue` (request `signDialog` with `mode: "export"`, see below), then `runExport` (`exportAs.ts`, the save dialog first, " signed" before the extension of the file captured when the command ran) on the editor's state when the dialog closes, the block still at its place or else the one of its number, never another. It signs the tab that showed when it ran (`activeTabId`, checked before the Sign dialog opens and when it's submitted), and nothing once another shows; the Sign dialog stops after its passphrase check when its request was closed meanwhile. The signature and certificate dialogs stay open across a tab switch: they work on the user's profile, not the document. The PDF's /Name is the certificate's name, else Settings ▸ Signing's, never the block's (the dialog warns when the chosen block names someone else, `namedNote`); the place is the one the page shows, the block's own (the dialog then shows `placeNote` instead of the field) else the one typed, and that is what /Location gets and what is remembered, with the initials' choice (`signingInitials`, localforage like `signingPlace`, written once a signed PDF is).

- **The boxes:** the export's engine gives the filled in block's box (`ExportResult.signatureBox`, `PdfJob.signedPos`) and those of the other blocks (`ExportContext.others` → `otherBoxes`, `PdfJob.otherPos`; null for one not on the pages), display points from the page's top left, read before the engine is freed, on the shared engine and in the worker alike.
- **The update** (`finishExport`, the plan from `exportRequest` in `src/signing/exportPlan.ts`, one `signing_sign_pdf` in body mode): `others` an empty field per other block named after its name, else its role; the initials (`src/signing/initials.ts`: `INITIALS_STAMP`, 56 × 28 pt, `INITIALS_MARGIN` 36 pt from the bottom and the side chosen, `initialsRect` on the layout's page size) one repeated stamp as part 1, made with `stampPdf` after `loadMarks`; and for a digital signature the field over the block (no box, nothing written). Without a passphrase it's the stamps-only update, and only with others or initials: else the PDF is written as krilla made it. A failure writes nothing, and says so (`signingFailure`, with how to sign without a timestamp while a server is set).

## The Sign dialog (`SignDialog.vue`, `signDialogModel.ts`)

One dialog for both flows, `SignDialogRequest.mode` `"export"` or `"pdf"` (a PDF tab), closed by `closeRequests` before a tab switch; it hands `SignChoices` (`pos`, null in a PDF tab, `place`, `reason`, `passphrase`, null for no digital signature, `initials`, `open`) to `submit`. Rows: **Sign as** (`#sign-dialog-how`, a `MenuButton` select: "‹name› · your certificate", "No digital signature (only the visible signature)", then Create your certificate… without one and Manage…, which closes the dialog for Settings ▸ Signing; its menu gives the focus to the passphrase when there is one; a certificate made from it switches to it), **Sign in** (export, several blocks), **Initials** (`#sign-dialog-initials`, On every page, with the corner below it; disabled with `initialsProblem`: the request's `initials.reason`, e.g. a PDF others signed, else no saved initials, with Add your initials…; a PDF tab follows it at once through `setInitials`), **Place**, **Reason** (`plan.reason`), **Passphrase** (selected on errors). Notes: the time source, a PDF tab's `stampNote` (an invisible signature without a signature stamp, or for no digital signature "Place your signature on the page first…", and Sign… waits) and `emptyFieldsNote`, the others' fields in the export. `confirmPages` (an imported Word document) adds "I checked every page", which Sign… waits for (`canSign`); a PDF tab has "Open the signed PDF" (on).

## Stamps and signing received PDFs (native, `signing/pdf/`)

- One command, `signing_sign_pdf`: the header `blank-signing` is percent-encoded JSON `{ passphrase, source, plan }` (`SignRequest` in `src/signing/ipc.ts`, `Header` in `commands.rs`), the body the parts (`encodeParts`: a little-endian u32 count, then each part as a little-endian u64 length and its bytes). `source` is `{kind:"body"}` (the export flow: part 0 is the PDF) or `{kind:"tab", tab, path, sha256, fills}` (read again, `fileChanged`/`fileMissing` when it isn't the file the tab opened; the fills come from the tab's helper as their own revision through `pdf_view::filled_bytes`, on the blocking thread). `plan.stamps[].part` and the signature's `stamp` index the parts. A `null` passphrase writes the stamps and fields alone, no signature. Pages are from 1, rects display points (`PageGeometry` converts).
- `xobject.rs`: a stamp's one-page PDF (from Blank's engine) becomes a Form XObject, `/BBox [0 0 w h]`: loaded with bounded `LoadOptions`, every object its resources reach copied once with new ids (through a queue, so cycles end; page tree and structure objects become null), `/StructParent(s)` dropped, marked content with an `/MCID` turned into `/Artifact BMC`. For a PDF/A-1 target (`pdfa_part`, the XMP's `pdfaid:part`) the transparency goes: no `/Group`, soft masks of images drawn over white, graphics states opaque.
- `stamp.rs`: `draw_on_page` wraps the page's content in `q … Q` and draws its stamps after it (`cm` from `PageGeometry::placement`, so /Rotate, the crop box's origin and UserUnit hold), with a direct copy of the page's effective (maybe inherited) `/Resources`. A repeated stamp is one XObject drawn on every page at the same place, moved (and made smaller) into smaller pages (`clamp`). `appearance` is a widget's appearance: empty, or a stamp fitted into it.
- `sign.rs` (`update_pdf`): the stamps, then empty `/Sig` fields for the others who sign ("Signature of ‹name›", unique, no periods), then the signature: an existing empty field keeps its name and gets `/V` and the stamp as its `/AP /N`; a new `SignatureN` shows its stamp in the page content on a PDF nobody signed yet and as its appearance on signed or certified ones; or invisible. Without a signer, a signature's stamp goes into the page content.
- `rules.rs` (`Rules::read`, once per update): DocMDP P, signed, FieldMDP locks. `signing_pdf_rules(path)` (`pdf_rules`) gives the PDF tab's signing tools the same as `PdfRules { signed, docmdp, encrypted, damaged, locked }` (`load_for_update`'s `Restricted` is `encrypted`, its other failures `damaged`; `locked` the full names an earlier signature locked), read on a blocking thread; see `pdf.md`, "Stamps". Refused natively (`Refusal`): anything on P=1 (`Certified`), stamps in the pages' content of signed or certified PDFs (`SignedPages`), a field that isn't there, is signed or locked, encrypted PDFs (`Restricted`, `load_for_update`).
- After the update, `verify_pdf` must find exactly one new signature, valid and covering the whole file (none for a stamps-only update), and every earlier one, known by its byte range, as valid as it was; else the generic sentence and nothing is returned.
- **The webview's side** (`signReceived`, `src/pdf/sign.ts`: Sign…, Mod-S in a PDF tab, the close question's Sign…): `loadMarks`, `loadCertificate`, then the Sign dialog in mode `"pdf"` (`stamped`: a signature stamp is placed; `emptyFields`: the places not filled; `initials` from a repeated initials stamp, its `reason` `toolRefusal("initials")`; `setInitials` (`initialsSetter`) repeats the initials placed, else adds them in the corner chosen of the first page, moves them to another corner, and off takes the repeat off, or the stamp it added). On submit: the save dialog (`suggestPath` with " signed", or `window.blankTestSavePath` where `__TEST_HOOKS__`), then each stamp's `stampPdf` at its rect's size (`scaledSpec`) after `loadMarks`, then `signPdf` with `source: { kind: "tab", tab, path, sha256, fills }` and `receivedPlan` (`src/pdf/receivedPlan.ts`, pure: the stamps in reading order as the parts; signed digitally, the signature stamp on a `/Sig` field (else the first) is `signature: existing` with its field, or `new` at its spot, the others page content; without a passphrase every stamp is page content and the signature invisible; `others` empty). Then `writeFile`, `signingPlace` remembered, `clearSheet` (nothing unsaved; `syncFills` empties the helper's form), "Signed and saved as ‹file›", and with "Open the signed PDF" `openPaths([dest])` (imported when it runs: the tabs import this module). A failure is a notification with `signingFailure`'s sentence ("… Nothing was saved."), and nothing is written; the passphrase is checked in the dialog first.
- Tests: `commands/received.rs` on the PDF tab's fixtures with stamp PDFs made by lopdf; `pdftotext -bbox -cropbox`, `pdfsig -nssdir <temp>` and `qpdf --check` where installed (CI never skips them).
